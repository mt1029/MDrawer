# MDrawer 專題規格書

以資料夾為核心的個人 Markdown 筆記空間（PWA）。使用者自己建立、自己整理目錄，系統只負責存放、預覽、離線使用與匯出。

## 1. 專案概述

- **目標使用者**：作者本人，以及想自己掌控目錄的學生。一人一個私人空間。
- **核心價值**：目錄由使用者決定，沒網路也能看、能寫，貼上截圖就能插圖，隨時能把完整資料帶走。
- **形態**：PWA，可安裝到手機與電腦主畫面。
- **AI 的角色**：只用在開發過程（設計討論、寫程式、除錯、測試、規格審查），產品本身不內建 AI 功能。

**刻意不做**

- AI 自動分類、標籤、整理目錄。目錄由使用者決定是設計取捨，不是缺功能。
- 多人協作與即時共同編輯。
- 公開分享連結。

## 3. 功能範圍

分三層，由上往下完成。每一層做完都是可以繳交、可以 demo 的版本，時間不夠就從後面砍。

### 核心層 C（目標 12/1）

| 功能 | 驗收條件 |
| --- | --- |
| 帳號登入 | 能註冊、登入、登出。A 帳號看不到 B 帳號的任何資料 |
| 資料夾樹 | 能建立、改名、移動、刪除。同層名稱不重複，至少 5 層 |
| Markdown 編輯與預覽 | 即時預覽，支援標題、清單、表格、程式碼區塊、圖片。預覽經 XSS 過濾 |
| 貼圖上傳 | Ctrl+V 貼圖，前端壓縮成 WebP（Safari 為 JPEG）後上傳並自動插入，壓縮、上傳時顯示原始與壓縮後的大小。11/26 起圖片放在筆記所在的資料夾，筆記用相對路徑引用（見下方「圖片放進資料夾」） |
| PWA 與部署 | 可安裝、有圖示，離線時能開啟 App 外殼，已部署到公開網址 |

### 標準層 S（目標 12/4～12/9）

| 功能 | 驗收條件 |
| --- | --- |
| ZIP 匯出 | 保留資料夾結構，圖片放在它所在的資料夾、筆記用相對路徑引用，解壓後可直接閱讀 |
| 離線 L1 | 每次連線時把所有資料鏡像到 IndexedDB，斷線時可開啟並閱讀全部筆記（唯讀） |

| 3. 編輯器 | 預設只顯示編輯區，右上角的眼睛圖示切換成 Markdown 預覽（再按一次回到編輯，游標回到編輯框）；在眼睛上按右鍵／長按／Shift+F10，選單裡有「只顯示編輯區」「只顯示預覽」「並排」三種，目前的打勾。並排在大螢幕左右、小螢幕上下（各佔畫面四成，在框裡捲動）。「並排」記在這台裝置，換筆記、重新整理都保持；「只看預覽」是暫時的，每篇筆記從編輯開始。右上角的插入圖片也只放圖示。預覽看不到時不轉換、不取圖片網址。標題區：名稱上方顯示所在的資料夾路徑，只到資料夾、結尾加 `/`（例如 `/課程/第一週/`，最上層為 `/`）；名稱同一行接著儲存狀態，最右邊是插入圖片與眼睛圖示，不另外佔一行，編輯區多一點空間；名稱太長時儲存狀態與圖示換到下一行。不顯示最後修改的時間（在樹上游標停留時看）。編輯區左邊有行號（類似 VS Code）：很長的行自動換行時，行號只在第一列；超過 99 行時行號欄才加寬。游標所在的行整行換成灰色（深色模式是亮一點的灰），行號變成內文的顏色；選取文字時不標示整行，只把游標那一端的行號變亮；編輯區沒有焦點時不標示。預覽的四周留白與編輯區相同，第一行的高度對齊 | 三種顯示方式都能切換，切換時不會遺失還沒存的內容。行號在中文、英文、長網址自動換行時都對得上 |

| 5. 帳號 | 上方列只剩 MDrawer 與右邊的選單圖示（三條橫線；沒有換頭貼的功能，所以不用頭像）。點開是選單：最上面顯示登入的 email（不能選，太長時截斷，游標停留看完整的），下面是「匯出 ZIP」（離線時變灰並說明原因）、「登出」（沿用第 6 節的登出保護），之後的設定也放這裡。選單從圖示往下開、右邊對齊圖示；再按一次圖示、點外面或 Esc 關閉 | 選單可以用鍵盤操作（Enter、空白鍵或下鍵打開，上下鍵移動，Esc 關閉後焦點回到選單圖示） |
| 6. 搜尋 | 搜尋這台裝置上所有筆記的名稱與內容（即加分層的全文搜尋），資料在本機，離線也能用。不分大小寫、照字面找（. **圖示規則**

- 功能按鈕一律用 Tabler Icons，只放圖示、不放文字。游標停留時以 `title` 顯示說明，另加 `aria-label` 給螢幕閱讀器。`title` 在觸控裝置上看不到，螢幕閱讀器也不一定會唸。
- 右鍵選單與右上角的選單是圖示加文字。
- 圖示依視覺重心對齊，不用外框對齊：把圖示模糊後只留下看得到的部分，用它的重心與左緣來對齊。按鈕裡的圖示依重心置中，選單裡的圖示左緣對齊文字。量測後看起來仍然偏的圖示，在腳本裡另外加肉眼微調（目前是登出圖示：左邊的長方形太搶眼）。量測值在 `src/components/iconOptics.ts`，由 `scripts/icon-optics.mjs`（`npm run icons:optics`）產生，新增圖示後要重跑。
- 對話框的按鈕、狀態訊息、登入表單維持文字，尤其是刪除這類無法復原的操作要寫清楚。

### 圖片放進資料夾（11/26 追加）

原本上傳的圖片只在 Storage，使用者看不到、改不了名稱、刪不掉（刪除筆記還會留下孤兒檔）。改成圖片跟筆記一樣是資料夾裡的項目，由使用者自己管理（資料表修改見第 5 節）。

| 項目 | 做法 | 驗收條件 |
| --- | --- | --- |
| 資料夾裡的圖片 | 檔案總管顯示圖片，跟筆記一樣可以改名、移動、複製、刪除（離線也可以）；資料夾右鍵「上傳圖片」可以一次選多張；選了圖片時右側顯示預覽與寬 × 高 | 上傳同名的圖片自動加編號（照片 (2).webp）；複製的圖片共用同一個檔案 |
| 筆記裡的圖片 | 筆記用相對路徑引用：`![](架構圖.webp)`、`![](../共用/logo.webp)`、`![](/課程/logo.webp)`；貼上、拖進編輯區、插入圖示都把圖片放進筆記所在的資料夾再插入連結；把檔案總管的圖片拖進編輯區插入相對路徑 | 預覽找得到圖片；不存在的路徑顯示虛線框；離線時找得到是哪一張（沒載入過的顯示「離線時無法載入圖片」） |
| 刪除與匯出 | 刪除的圖片進垃圾桶，檔案留著（11/27 起）；永久刪除後，雲端沒有其他圖片項目（包含垃圾桶裡的）用到同一個檔案時才刪掉 Storage 的檔案；匯出 ZIP 時圖片放在它所在的資料夾、筆記照原樣存檔 | `npm run test:sync` 在真的 Supabase 上檢查清檔案；解壓後其他 Markdown 編輯器找得到圖片 |

改名或移動圖片時，筆記裡的連結不會自動更新（第 8 節）。11/26 之前的 `![](img:<uuid>)` 寫法已全部搬進資料夾，並移除這種寫法的支援。

### 匯入（加分層，11/26 完成）

把電腦裡的 Markdown 筆記（例如其他編輯器的資料夾、MDrawer 匯出的 ZIP）搬進來，保持原本的資料夾結構，圖片照樣顯示。

| 項目 | 做法 | 驗收條件 |
| --- | --- | --- |
| 入口 | 資料夾與空白處的右鍵選單：「匯入檔案」（可以多選 `.md`、`.markdown`、圖片、`.zip`）、「匯入資料夾」（整個資料夾）；大螢幕也可以從電腦把檔案、資料夾、ZIP 拖到樹裡的資料夾或空白處。匯入到那個資料夾（空白處是最上層） | 拖曳時標示要放進去的資料夾；完成後選取匯入的項目，側欄上方顯示匯入了幾個資料夾、筆記、圖片 |
| 轉換 | `.md`、`.markdown` 變成筆記（名稱去掉副檔名，`\r\n` 換成 `\n`）；圖片壓縮後變成圖片項目，已經是 WebP、JPEG 而且不超過 2 MB、2560px 的照原樣上傳（匯出的 ZIP 匯入回來畫質不變）；ZIP 只有一個最上層資料夾時就是那個資料夾，不然放進以 ZIP 檔名命名的資料夾；其他檔案略過並說明幾個，隱藏檔、`__MACOSX`、`.DS_Store` 直接忽略；名稱裡的 `/ \ ..` 換掉，太長截短 | 撞名一律加「 (2)」，不覆蓋、不合併原有的項目；一個檔案失敗不影響其他的，失敗的列出第一個的原因 |
| 圖片連結 | 圖片建立後才知道名稱（壓縮後的副檔名、撞名的編號、資料夾被加編號），筆記裡指到匯入圖片的連結（`![](…)` 與參考式連結的定義）改成新的相對路徑；原本的寫法還找得到同一張圖就不改，`/` 開頭的改成相對路徑；程式碼區塊、行內程式碼裡的不改 | 匯入後預覽找得到圖片；MDrawer 匯出的 ZIP 匯入回來，筆記內容與圖片（位元組）都跟匯出前一樣 |
| 離線 | 筆記、資料夾離線也能匯入（先存本機，連線後同步）；圖片要上傳，離線時略過並說明幾張 | 離線匯入後連線，筆記正常同步 |

一次最多讀 1000 個檔案（含不支援的），避免不小心拖進很大的資料夾。限制見第 8 節。

### 垃圾桶（加分層，11/27 完成）

刪除本來就只在雲端標記 `deleted_at`（其他裝置才同步得到），垃圾桶列出這些項目，可以還原或永久刪除。資料在雲端，只在連線時能用（資料表修改見第 5 節）。

| 項目 | 做法 | 驗收條件 |
| --- | --- | --- |
| 面板 | 左側圖示欄的垃圾桶圖示（小螢幕在其他面板的標題列，第 4 步），跟檔案總管、搜尋一樣放在側欄。每一筆顯示名稱、原本的位置、刪除的時間，資料夾加上「含 N 個項目」，新刪除的在前；標題列有重新整理、清空垃圾桶。離線時說明「離線時無法使用垃圾桶」 | 打開時先推送這台裝置剛刪除的項目，剛刪的看得到 |
| 一起刪除的合成一筆 | 同一次刪除（資料夾連同裡面的項目）用同一個刪除時間（第 5 節其他設計規則），垃圾桶依此分組；資料夾刪除之前就先刪掉的項目是另外一筆 | 還原資料夾時，之前另外刪的項目留在垃圾桶 |
| 選取與選單 | 跟檔案總管一樣（11/27 統一）：點一下只選取，⌘／Ctrl 點選加入或取消、Shift 點選選一段範圍，點空白處取消選取；右鍵、長按、選單鍵開選單「還原」「永久刪除」，在多選的項目上是整個選取（「還原 N 筆」「永久刪除 N 筆」），不然只有那一筆；Delete（Mac 為 ⌘⌫）永久刪除，Esc 取消多選。選取的項目游標移過去維持選取的顏色 | 鍵盤、滑鼠、觸控都能操作 |
| 還原 | 還原放回原本的資料夾，那個資料夾已經不在（也在垃圾桶或已永久刪除）時放到最上層並說明；撞名時加「 (2)」（這台還沒同步到、雲端才有的同名項目也一樣）。一次還原好幾筆時依畫面順序（新刪除的先），原本的資料夾在不在用還原當時的資料判斷，所以同時選了資料夾和之前另外刪的裡面的項目，項目會回到資料夾裡。還原後同步，檔案總管馬上看得到 | 還原的資料夾連同裡面一起回來；列出之後被別台還原或改過時說明「垃圾桶的內容剛被其他裝置改過」 |
| 永久刪除、清空 | 確認對話框寫明無法復原。不實際刪列（當時離線的裝置要能同步到），標記 `purged_at` 並清掉筆記的內容，垃圾桶不再列出 | `npm run test:sync` 在真的 Supabase 上檢查：B 看不到、刪不到 A 的垃圾桶 |
| 圖片檔 | 刪除時不刪檔案（還原後要能顯示）；永久刪除後，沒有其他圖片項目（包含垃圾桶裡還能還原的）用到時才刪掉 Storage 的檔案 | `npm run test:sync` 檢查：複製的另一張還在、或還在垃圾桶時保留 |
| 刪除對話框 | 說明改成「刪除的項目會移到垃圾桶，連線時可以從垃圾桶還原」 | |

### 停損規則

- 12/9 晚上 L2 還沒通過驗收，就停在 L1。報告把 L2 寫進「限制與未來工作」，附上已完成的部分與卡關原因。

## 4. 系統架構與技術選型

Supabase 負責登入、雲端資料與跨裝置同步。從 L1 起，瀏覽器的 IndexedDB 也存一份完整資料，離線時改讀本機。

- UI 只呼叫 `repo` 介面（`listChildren`、`getNode`、`createNode`、`updateNode`、`moveNode`、`copyNode`、`deleteNode`）。C 層時它直接讀寫 Supabase；L1 時連線照常讀寫 Supabase 並更新本機副本，斷線改讀 IndexedDB；L2 時改成先讀寫 IndexedDB 並在背景同步。UI 程式碼不必重寫。
- 登入由前端直接向 Supabase Auth 完成。圖片檔在連線時直接上傳到 Storage；圖片項目（名稱、位置）跟資料夾、筆記一樣存在 `nodes`，離線也能改名、移動、刪除。

| 用途 | 選擇 |
| --- | --- |
| 前端 | Vite + React + TypeScript |
| 後端 | Supabase（Auth、Postgres、Storage），`@supabase/supabase-js` |
| 本機資料庫 | IndexedDB，搭配 `idb` |
| Markdown | `markdown-it`（`html: false`）＋ `DOMPurify` |
| 圖片壓縮 | Canvas 轉 WebP（Safari 改存 JPEG） |
| ZIP 匯出 | `jszip` |
| PWA | `vite-plugin-pwa` |
| 託管 | Vercel（Hobby 免費方案） |

**Supabase 免費方案**（2026/11/23 依[官方定價頁](https://supabase.com/docs/pricing)確認）

- 閒置一週會被暫停，最多 2 個啟用中的專案，檔案儲存 1 GB。
- demo 與繳交前一週要登入操作一次，確認專案沒有被暫停。
- demo 專案可在 Auth 設定關閉「註冊需信箱驗證」，並先建好兩個測試帳號。

## 5. 資料表設計

資料夾、筆記與圖片共用一張 `nodes` 表，以 `parent_id` 組成樹，移動項目只改一個欄位。圖片檔放在 Storage，`nodes` 只記圖片的名稱、位置與檔案的 uuid（11/26 起，原本圖片不進資料表）。

| 欄位 | 型別 | 說明 |
| --- | --- | --- |
| `id` | uuid，主鍵 | 由前端產生，讓離線時也能建立新項目 |
| `user_id` | uuid | 擁有者，預設 `auth.uid()`。刪除帳號時資料一併刪除 |
| `parent_id` | uuid，可為空 | 上層資料夾，根目錄為空。必須是同一個使用者的項目，且不能是自己 |
| `type` | text | `folder`、`note` 或 `image`（11/26 起） |
| `name` | text | 顯示名稱，同一資料夾下不可重複（不分大小寫） |
| `content` | text，可為空 | 筆記內容；圖片為 Storage 裡圖片檔的 uuid（複製的圖片共用同一個檔案，所以不放在 `id`） |
| `version` | integer | 由觸發器寫入：新增時為 1，每次更新加 1，用來偵測衝突 |
| `created_at`、`updated_at` | timestamptz | 由觸發器以伺服器時間寫入，前端傳的值會被覆蓋 |
| `deleted_at` | timestamptz，可為空 | 標記刪除，不實際刪列，讓其他裝置同步到「已刪除」。值是在裝置上刪除的時間，同一次刪除的項目都一樣（垃圾桶用來分組） |
| `purged_at` | timestamptz，可為空 | 永久刪除（11/27 起，垃圾桶）：一樣不實際刪列，筆記的內容清掉；垃圾桶只列出 `deleted_at` 有值、`purged_at` 為空的列 |

實際執行的檔案是 `supabase/migrations/20261123000000_create_nodes.sql`，執行與測試方式見 `docs/database.md`。兩者內容應保持一致。11/26 加上圖片的修改在 `supabase/migrations/20261126000000_images_in_folders.sql`：`type` 的檢查改成 `folder`、`note`、`image`，並要求圖片的 `content` 是 uuid（RLS、觸發器、索引不變）。11/27 垃圾桶的修改在 `supabase/migrations/20261127000000_trash.sql`：只加 `purged_at` 欄位（RLS、觸發器、索引、其他限制不變；要先執行再部署新版前端）。

```sql
-- 資料夾與筆記共用一張表，以 parent_id 組成樹
create table public.nodes (
  id uuid primary key,                        -- 由前端產生，離線時也能建立新項目
  user_id uuid not null default auth.uid()
    references auth.users (id) on delete cascade,  -- 刪除帳號時一併刪除資料
  parent_id uuid,                             -- 上層資料夾，根目錄為 null
  type text not null check (type in ('folder', 'note')),
  name text not null check (
    char_length(name) between 1 and 100
    and name !~ '[/\\]'
    and position('..' in name) = 0
  ),
  content text,
  version integer not null default 1,         -- 由觸發器維護，用來偵測衝突
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  deleted_at timestamptz,                     -- 標記刪除，不實際刪列

  -- 上層資料夾必須屬於同一個使用者。外鍵檢查不受 RLS 限制，
  -- 只用 parent_id 單欄外鍵的話，別人可以把項目掛到你的資料夾下。
  constraint nodes_user_id_id_key unique (user_id, id),
  constraint nodes_parent_fkey foreign key (user_id, parent_id)
    references public.nodes (user_id, id),
  constraint nodes_parent_not_self check (parent_id is null or parent_id <> id)
);

-- 同一層未刪除的項目不可同名，且不分大小寫（避免 ZIP 在 macOS、Windows 解壓時撞名）。
-- 根目錄的 parent_id 為 null，用 coalesce 處理，不依賴 PG 版本
create unique index nodes_unique_name on public.nodes (
  user_id,
  coalesce(parent_id, '00000000-0000-0000-0000-000000000000'::uuid),
  lower(name)
) where deleted_at is null;

create index nodes_tree_idx on public.nodes (user_id, parent_id);
create index nodes_sync_idx on public.nodes (user_id, updated_at);

-- version、created_at、updated_at 一律由資料庫寫入，前端傳來的值會被覆蓋
create function public.nodes_touch() returns trigger
language plpgsql
set search_path = ''
as $$
begin
  if tg_op = 'INSERT' then
    new.version := 1;
    new.created_at := now();
  else
    new.version := old.version + 1;
    new.created_at := old.created_at;
  end if;
  new.updated_at := now();
  return new;
end $$;

create trigger nodes_touch before insert or update on public.nodes
  for each row execute function public.nodes_touch();

-- 每個人只能存取自己的資料
alter table public.nodes enable row level security;

create policy own_nodes on public.nodes for all
  to authenticated
  using (user_id = (select auth.uid()))
  with check (user_id = (select auth.uid()));

-- 2026/5/30 之後建立的 Supabase 專案，新資料表不會自動開放給 Data API，要明確授權。
-- 只開放給已登入使用者；未登入（anon）一律不能存取。
revoke all on table public.nodes from anon;
grant select, insert, update, delete on table public.nodes to authenticated;
```

### 圖片儲存

- 建立私有 bucket `images`，大小上限 2 MB，只允許 `image/webp` 與 `image/jpeg`。前端一律用 Canvas 轉成 WebP；Safari（含所有 iPhone 瀏覽器）的 Canvas 無法輸出 WebP，改存 JPEG，透明處補白。
- 檔案路徑為 `{user_id}/{uuid}`，不加副檔名，格式記在檔案的 Content-Type。存取政策要求完整路徑必須是「自己的 id/UUID」。實際執行的檔案是 `supabase/migrations/20261123010000_create_images_bucket.sql`：

```sql
-- 私有 bucket：單檔上限 2 MB，只接受 WebP 與 JPEG
insert into storage.buckets (id, name, public, file_size_limit, allowed_mime_types)
values ('images', 'images', false, 2097152, array['image/webp', 'image/jpeg']);

-- 只能存取自己的圖片，而且路徑必須是「自己的 id/UUID」
create policy own_images on storage.objects for all
  to authenticated
  using (
    bucket_id = 'images'
    and name ~ ('^' || (select auth.uid())::text || '/[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$')
  )
  with check (
    bucket_id = 'images'
    and name ~ ('^' || (select auth.uid())::text || '/[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$')
  );
```

- 圖片是 `nodes` 的一列（`type` 為 `image`），`content` 是圖片檔的 uuid。筆記用相對路徑引用，從筆記所在的資料夾算起：`![](架構圖.webp)`、`![](../共用/logo.webp)`、`![](/課程/logo.webp)`（`/` 開頭從最上層算，名稱不分大小寫）。預覽時先用這台裝置的資料找到圖片項目（離線也可以），再用它的 uuid 以 `createSignedUrls` 取得 Storage 的短效簽名網址（有效 1 小時）並快取。匯出 ZIP 時圖片放在它所在的資料夾，筆記照原樣存檔，連結不用改。bucket 不必公開。
- 替換必須在 DOMPurify 過濾之前完成：相對路徑不換掉的話，瀏覽器會當成本站的網址去讀。做法是在 markdown-it 產生 `<img>` 時換成簽名網址，再交給 DOMPurify（換上的網址仍會被過濾）。
- 貼上、拖進編輯區、插入圖示：壓縮後上傳，放進筆記所在的資料夾再插入 `![](名稱)`。貼上的截圖命名為「截圖-年月日-時分秒」，其他用原檔名，副檔名換成 `.webp` 或 `.jpg`；撞名時編號放在副檔名前面；名稱有空白或括號時連結寫成 `![](<名稱>)`。檔案總管的圖片拖進編輯區時插入從筆記到圖片的相對路徑。
- 刪除圖片：圖片項目進垃圾桶，檔案留著（11/27 起；之前是推送刪除後就刪檔案）。永久刪除後，雲端沒有其他還沒永久刪除的圖片項目（包含垃圾桶裡的）用到同一個檔案時，才刪掉 Storage 的檔案（失敗不影響永久刪除，只是留下用不到的檔案）。
- 11/26 之前的筆記寫成 `![](img:<uuid>)`，已用一次性的轉換搬進資料夾，之後移除這種寫法的支援。
- 剛貼上的圖片同樣是上傳後再取簽名網址顯示，不用本機的 `blob:` 網址，因為 DOMPurify 預設也會移除 `blob:`。
- CSP 由 `vite.config.ts` 在打包時寫入 `index.html`：`script-src 'self'`；`img-src` 與 `connect-src` 只允許自己的網域與 Supabase 專案網域，不開放 `blob:` 與外部圖片。開發模式不加 CSP，因為 Vite 的熱更新需要行內 script。

### 其他設計規則

- 刪除資料夾時，前端遞迴把它與所有子孫都標上 `deleted_at`。同一次刪除用同一個時間（在裝置上按下刪除的時間，記在待同步佇列，推送時寫入），垃圾桶靠它分辨哪些是一起刪的；推送刪除時一併把 `purged_at` 設成空，被修改還原過的永久刪除項目再刪除時才會回到垃圾桶。
- 移動資料夾時，前端要檢查目標不是自己或自己的子孫，避免形成循環。
- 複製時，資料夾連同所有子孫一起複製，每個項目都是新的 `id`，放進待同步佇列（推送時父先子後）；目標資料夾裡已經有同名的項目時，名稱加上「 (2)」；同樣不能複製到自己或自己的子孫底下。複製圖片時新的圖片項目共用同一個圖片檔，不重新上傳（離線也能複製）。

## 6. 離線與同步

### L1 離線唯讀（約 1 天）

> L2 完成後，離線也能寫入，「僅能閱讀」與「連線時讀雲端」的部分由下方 L2 取代；副本歸屬、登入權杖過期的處理沿用到 L2。

每次 App 啟動與恢復連線時，把該使用者所有未刪除的 `nodes` 整批寫入 IndexedDB。連線時在這台裝置新增、修改、移動、刪除成功，或開啟筆記讀到最新內容，也一併寫進副本。斷線時 UI 改讀 IndexedDB，編輯功能顯示「離線中，僅能閱讀」，圖片位置顯示「離線時無法載入圖片」。不需要佇列。

- **副本歸屬**：副本記下屬於哪個帳號。換成別的帳號登入時先清除；登出（包含在其他分頁登出、被伺服器判定失效）時清除。
- **登入權杖過期**：權杖約 1 小時過期，離線時無法更新，supabase-js 會回報「未登入」。這時若本機還有副本（登出一定會清除，所以代表沒有登出），就用副本記錄的帳號開啟（L1 唯讀，L2 照樣可以在本機讀寫）；恢復連線後立刻重試更新權杖，成功才開始同步，更新被拒絕就當成被強制登出處理（見 L2 第 6 點）。
- **連不到伺服器**：瀏覽器顯示有連線但請求失敗時，讀取改用副本，寫入照常顯示連線錯誤。
- **整批下載期間的修改**：以這台裝置剛改的為準，不被下載到的舊資料蓋掉，已刪除的項目也不會被加回來。
- **恢復連線時**：資料夾樹改從雲端重新載入；斷線前沒存到的內容自動補存；正在看的筆記若沒有未存的修改，就從雲端重讀一次。離線時讀的是副本，可能比雲端舊，不重讀的話接著編輯會蓋掉別台裝置的修改。

### L2 離線可寫與同步（約 3～4 天）

UI 的所有讀寫都在 IndexedDB 完成，連線時在背景同步。程式在 `src/lib/localDb.ts`（資料庫結構與佇列）、`repo.local.ts`（本機讀寫）、`sync.ts`（推送、拉取、衝突）、`cloud.ts`（同步用的 Supabase 請求）、`mirror.ts`（同步時機、帳號、登出保護），運作與驗證見 `docs/offline.md`，真實 Supabase 的檢查為 `npm run test:sync`。

1. **本機寫入**：所有修改先寫入 IndexedDB 並放入待同步佇列。同一個項目的多次修改合併成一筆，記下改了哪些欄位，以及修改前的雲端版本：`base_version` 與當時的名稱、位置、內容，衝突時用來判斷雲端改了什麼。名稱規則、同層不可同名、不能移進自己底下，先在本機檢查一次。本機新增的項目 `version` 為 0，顯示用的時間不送到資料庫。
2. **推送時機**：App 啟動、`online` 事件、登入恢復時、固定間隔（30 秒），以及在這台裝置修改後 2 秒。同一個瀏覽器的多個分頁用 Web Locks 輪流同步。
3. **推送順序**：先刪除（子項目先、資料夾後），再新增（父先子後），最後修改（照修改的順序）。
   - 新增父先子後：否則離線時先建資料夾、再在裡面建筆記，會因為 `parent_id` 外鍵而失敗。
   - 刪除子項目先：反過來的話，其他裝置剛好在中間同步，會看到「資料夾已刪除、裡面的還在」而把它們移到根目錄，被刪的項目就保留下來了。
   - 刪除排最前面：「刪掉舊的、再建同名的」才不會撞名。
4. **推送方式**
   - 新項目：`upsert`，設 `onConflict: 'id'`、`ignoreDuplicates: true`，重送也安全。沒有回傳資料列代表之前已經送過，以雲端那筆為底，把不一樣的欄位當成修改推送。
   - 既有項目：`update ... where id = ? and version = base_version`，並要求回傳資料列。有回傳代表成功，沒有回傳代表雲端版本比較新，進入衝突處理。
   - 推送期間這個項目又被修改的話，新的修改留在佇列，以剛推送的版本為新的基礎，下一輪再推。
   - 斷線就中止這一輪，佇列保留。其他錯誤記在該筆，繼續推送其他項目，下次同步再試。
5. **拉取**：推送完成後，抓 `updated_at >= 本機記錄的最後一筆雲端 updated_at 往前 10 秒` 的所有列（含已標刪除者），用 `id` + `version` 去掉重複後寫回 IndexedDB。往前多抓是因為觸發器的 `now()` 是交易開始的時間，晚 commit 的修改時間可能比上次看到的還早。分頁時以 `(updated_at, id)` 接著上一頁往下讀，不用 offset，讀取期間有新的修改也不會漏掉。這台還有未推送修改的項目不覆蓋，留給下一次推送處理衝突。時間基準一律用雲端回傳的值，不用本機時鐘。
6. **登出保護**
   - 自己登出：佇列不是空的時，能連線就先同步一次；還有剩下的，要警告「有未同步的修改」，確認後才清除 IndexedDB。
   - 被強制登出（在其他分頁登出、在別處改密碼、全部登出）：沒有未同步的修改就清除；有的話先保留，登入畫面提示筆數，同一個帳號重新登入後自動同步。改用別的帳號登入時，先確認要不要刪除這些修改。

### 衝突處理

| 情況 | 處理方式 |
| --- | --- |
| 沒衝突（`version` 吻合） | 直接成功 |
| 兩端都改同一篇筆記的內容（雲端的內容與修改前不同） | 保留雲端版本，把本機版本另存為「名稱（衝突副本 日期時間）」放在同一資料夾，由使用者自行合併。側欄顯示提示 |
| 其他欄位衝突（改名、移動、刪除與修改交錯） | 以雲端最新版為底，重新套用本機這次的變更後再推送，較晚者為準。一邊改名或移動、一邊改內容時兩者都保留 |
| 一邊刪除、一邊修改 | 刪除不會蓋掉較新的修改：修改的那台推送時發現已刪除，就還原並套用修改；刪除的那台推送時發現版本不符，就保留雲端的版本 |
| 同名衝突（唯一索引錯誤 23505） | 自動在名稱後加「 (2)」重試，本機也跟著改名 |
| 編輯中的筆記剛好被同步改過 | 儲存時帶上「這次是根據哪個內容改的」，與本機目前的內容不同就把這次的內容另存為衝突副本，不蓋掉同步來的版本。沒有未存修改時，編輯器直接換成新內容 |

### 邊界情況

- 推送成功但回應遺失時，重送會因 `version` 不符被誤判為衝突。判為衝突時先抓雲端那筆，若內容與本機相同就視為已成功，不建立衝突副本。
- 本機新建的項目，如果父資料夾已被另一台裝置刪除，就把它放到根目錄。刪除只是標記 `deleted_at`，外鍵仍然成立，新增會成功但項目看不到，所以推送新增與移動前，要先到雲端確認上層存在且未刪除。
- 兩台交叉移動資料夾（A 把 P 移進 Q、B 把 Q 移進 P）時，資料庫不擋循環，兩個資料夾會從根目錄走不到。推送移動前在雲端往上檢查，會形成循環就改放根目錄。
- 拉取後檢查本機：上層已不存在（例如有修改而被保留的子項目）或形成循環的項目，移到根目錄並推送。

## 7. 安全性設計

| 風險 | 對策 | 驗證方式 |
| --- | --- | --- |
| 筆記含惡意 HTML 或 script（XSS） | `markdown-it` 設 `html: false`，輸出再經 DOMPurify 過濾，不使用未過濾的 `innerHTML`，正式版另設 CSP（只允許自己網域的 script） | 筆記貼入 `<script>`、帶 `onerror` 的圖片、`javascript:` 連結，確認預覽不執行 |
| 讀取或改動他人資料 | `nodes` 與 Storage 都啟用 RLS，限制為 `auth.uid()` | 用 B 帳號帶 A 的 id 查詢、更新、讀圖，應查無資料 |
| 惡意或過大上傳 | 前端先壓縮並轉 WebP（Safari 為 JPEG），bucket 限制大小（2 MB）與類型，存取政策限制路徑為「自己的 id/UUID」 | 上傳改副檔名的可執行檔、超大圖片，應被拒絕 |
| 名稱含路徑字元 | 資料庫 `check` 加前端驗證，匯出 ZIP 時再淨化一次：Windows、macOS 不允許的字元換成 `_`，Windows 保留名稱前加 `_`，淨化後撞名加「 (2)」 | 建立名稱含 `../` 的項目應失敗 |
| 金鑰外洩 | 前端只用 publishable key（舊版稱 anon key），secret key 與 service_role key 不進前端與 Git，`.env*` 列入 `.gitignore` | 檢查 Git 紀錄與打包檔。打包檔裡唯一的 `sb_secret_` 是 supabase-js 判斷金鑰格式的程式碼，不是金鑰 |
| 本機資料未加密 | 登出時清除 IndexedDB，有未同步修改要先警告。本機資料記下擁有者，換帳號登入時先清除，只開放給擁有者讀寫。例外：被強制登出時若有未同步的修改，保留到同一個帳號重新登入（第 6 節 L2 第 6 點） | 登出後檢查本機資料庫為空 |

## 8. 已知限制

報告「限制與未來工作」直接引用這一節。

- GIF 轉成 WebP 後會變成靜態圖。
- Safari（含所有 iPhone 瀏覽器）貼上的圖會存成 JPEG，透明背景會變成白色。
- 筆記不能顯示外部網站的圖片（CSP 限制），只能顯示自己上傳的圖。
- ZIP 匯出讀的是這台裝置的資料（包含還沒同步的修改），圖片仍要從雲端下載，所以離線時不能匯出；Storage 裡找不到的圖片不會放進 ZIP，筆記裡仍保留它的連結。
- macOS 終端機的 `unzip` 指令不認得 ZIP 的 UTF-8 檔名旗標，中文檔名會出錯；用 Finder 雙擊或 `ditto -x -k` 解壓則正常（ZIP 本身符合標準）。
- 離線時無法貼圖、也不能上傳或匯入圖片到資料夾，沒載入過的圖片無法顯示（簽名網址需要連線取得）。
- 圖片改名或移動後，筆記裡的連結不會自動更新（跟一般的檔案系統一樣），預覽會顯示找不到圖片。
- 一台刪除並永久刪除圖片、另一台離線時改了同一張圖片的名稱或位置：依「修改優先」會還原這張圖片，但檔案可能已經刪掉，還原後顯示找不到圖片（只刪除、還在垃圾桶的話檔案還在）。
- 垃圾桶的資料在雲端，離線時不能用；刪除的項目沒有自動清除（不會「30 天後永久刪除」），圖片檔要永久刪除後才會從 Storage 刪掉。
- 永久刪除不實際刪列：名稱、位置與刪除時間還留在資料庫（筆記內容會清掉），垃圾桶不再列出。另一台離線時改過的修改推上來，依「修改優先」照樣會把它還原。
- 11/27 之前刪除的項目每一列的刪除時間不同，在垃圾桶裡一個項目一筆（資料夾和裡面的項目分開列出）；其中的圖片檔在刪除時就已經刪掉，還原後顯示找不到圖片。
- 還原時，原本的資料夾已經不在就放到最上層，不會連同上層資料夾一起還原。
- 資料夾或圖片的名稱有 `< > : " | ? *` 等字元時，ZIP 裡的名稱會被淨化，筆記裡的相對路徑沒有跟著改，解壓後那些連結會斷。
- 不做即時同步，只在 App 啟動、恢復連線、每 30 秒與修改後 2 秒同步，另一台最慢約 30 秒才看到。同一個瀏覽器的另一個分頁，要等它自己同步或重新整理才會更新畫面。
- 離線期間登入權杖過期的話，修改先存在本機，恢復連線後要等 supabase-js 換到新權杖才會同步，最久約 1 分半（換權杖失敗後會冷卻 60 秒），重新整理頁面可立即重試。
- 不做欄位層級的合併，同一篇內容的衝突由使用者手動合併衝突副本；名稱與位置以較晚推送的為準。
- 拖曳只支援滑鼠；觸控裝置長按是開選單，移動與複製要用剪下、複製、貼上。剪下、複製只在 App 裡有效，不會放到系統剪貼簿。多選要用 ⌘／Ctrl、Shift 點選，觸控裝置只能一次處理一個項目。
- 匯入只支援 `.md`、`.markdown`、點陣圖片（PNG、JPEG、WebP、GIF、AVIF、BMP；HEIC 只有 Safari 讀得出來）與 ZIP，SVG 等其他檔案略過，筆記裡指到它們的連結照原樣留著。資料夾裡的 ZIP 不展開。
- 匯入只改寫圖片的連結；筆記之間的連結（`[下一篇](下一篇.md)`）不改（App 目前不支援用連結打開其他筆記）。
- 匯入資料夾、拖曳資料夾要瀏覽器支援（桌機的 Chrome、Edge、Safari、Firefox 都可以），手機能不能選資料夾看瀏覽器；拖曳只有大螢幕。舊工具壓縮、檔名不是 UTF-8 的 ZIP（例如舊版 Windows 的中文檔名），檔名會變成亂碼。
- 本機新建項目的父資料夾若已被另一台裝置刪除，或兩台交叉移動資料夾形成循環，項目會被移到根目錄。
- 拉取往前多抓 10 秒：commit 比交易開始晚超過 10 秒的修改可能漏掉。App 的每個請求都很短，實務上不會發生。
- 刪除很大的資料夾時，每個項目各推送一次（各自檢查版本），項目多時要一點時間。
- 被強制登出、留下未同步的修改時，重新登入前，未加密的資料會留在裝置上。
- 部分瀏覽器在儲存空間不足時可能清除本機資料，介面要提示定期匯出 ZIP。
- 本機資料未加密，登出時清除。
