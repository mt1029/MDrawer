# ZIP 匯出（標準層）

右上角選單裡的「匯出 ZIP」會把所有資料夾、筆記與圖片打包成 `MDrawer-年-月-日.zip` 下載。程式在 `src/lib/export.ts`（讀資料、下載圖片）與 `src/lib/exportPlan.ts`（決定路徑、改寫圖片連結）。

## ZIP 裡有什麼

```
MDrawer-2026-11-25.zip
├── images/                       所有圖片，檔名為圖片 id
│   ├── 85dd2d6d-….webp
│   └── 30c6caa3-….jpg            Safari 貼的圖是 JPEG
├── 課程/
│   ├── 第一週/
│   │   └── 課堂筆記.md            ![](../../images/85dd2d6d-….webp)
│   └── 問題_答案_.md              原名「問題:答案?」
├── 空的資料夾/                    空資料夾也會保留
└── 首頁.md                        ![](images/85dd2d6d-….webp)
```

- **資料夾結構**照 App 裡的樣子，筆記存成 `.md`；名稱已經是 `.md` 結尾的不會變成 `.md.md`。
- **圖片連結**改成從筆記所在位置出發的相對路徑：第二層的筆記是 `../../images/…`，最上層是 `images/…`。spec 寫的「相對路徑 `images/<uuid>.webp`」只對最上層的筆記成立，放在資料夾裡的筆記要往上回到根目錄。
- **檔名淨化**（spec 第 7 節）：Windows、macOS 不允許的字元 `< > : " | ? *` 換成 `_`，去掉結尾的點與空白，Windows 保留名稱（`CON`、`NUL`、`COM1`…）前面加 `_`。
- **撞名**：淨化後同名（不分大小寫）時加上「 (2)」。最上層的 `images` 保留給圖片，你自己的「images」資料夾會變成「images (2)」。
- **檔案時間**是筆記最後修改的時間。

## 驗證

| # | 操作 | 預期結果 |
| --- | --- | --- |
| 1 | 建幾層資料夾與筆記，其中幾篇貼上圖片，點右上角的選單圖示（三條橫線）→「匯出 ZIP」→「開始匯出」 | 對話框顯示資料夾、筆記、圖片的數量，瀏覽器下載 ZIP |
| 2 | 在 Finder（macOS）或檔案總管（Windows）雙擊解壓 | 資料夾結構與 App 一致，中文檔名正常 |
| 3 | 用 VS Code、Typora、Obsidian 等任一 Markdown 編輯器開啟解壓後的資料夾，打開有圖片的筆記 | 圖片正常顯示，包括放在兩、三層資料夾裡的筆記 |
| 4 | 離線時打開右上角選單 | 「匯出 ZIP」是灰的，不能按 |

自動化測試：`npm test` 裡的 `exportPlan.test.ts` 會實際打包成 ZIP 再讀回來，檢查每個圖片連結都指向 ZIP 裡存在的檔案。

## 已知限制

- **macOS 終端機的 `unzip` 指令**不認得 ZIP 的 UTF-8 檔名旗標，中文檔名會出錯。用 Finder 雙擊解壓、或在終端機用 `ditto -x -k 檔名.zip 目的資料夾` 就正常。Windows 10 以後的檔案總管、7-Zip 也都正常。
- **找不到的圖片**（例如 Storage 裡已被刪除）不會放進 ZIP，對話框會顯示數量。筆記裡仍保留它的相對路徑。
- **匯出讀的是這台裝置的資料**（離線 L2 起）：包含還沒同步到雲端的修改。圖片仍要從雲端下載，所以離線時不能匯出。剛打的字若還沒存好（右上角不是「已儲存」），不會出現在 ZIP 裡。
