# 離線 L1：離線唯讀（標準層）

連線時照常讀寫 Supabase，同時在瀏覽器的 IndexedDB（資料庫名稱 `mdrawer`）存一份所有資料夾與筆記的副本。斷線時改讀副本，可以開啟 App、展開資料夾、閱讀筆記，但不能新增、修改、移動、刪除。

程式：

- `src/lib/repo.local.ts`：讀寫 IndexedDB
- `src/lib/mirror.ts`：決定讀雲端還是讀副本，並維護副本
- `src/lib/useMirror.ts`：讓畫面取得副本狀態

UI 一樣只呼叫 `repo.ts`，不知道資料是從哪裡來的。

## 運作方式

| 情況 | 讀取 | 寫入 | 畫面 |
| --- | --- | --- | --- |
| 連線且已登入 | 雲端（同時更新副本） | 雲端（成功後寫進副本） | 側欄顯示「離線副本：時間 更新」 |
| 斷線 | 副本 | 回絕 | 上方提示「離線中，僅能閱讀」，寫入按鈕停用，編輯框唯讀 |
| 瀏覽器以為有連線，但連不到伺服器 | 雲端失敗後改讀副本 | 顯示連線錯誤 | 跟連線時一樣 |
| 離線期間登入權杖過期（見下方） | 副本 | 回絕 | 跟斷線時一樣 |

**副本什麼時候更新**

- App 開啟、恢復連線時：整批下載所有未刪除的資料，取代原本的副本。
- 在這台裝置新增、修改、移動、刪除成功後：把雲端回傳的結果寫進副本。
- 連線時開啟筆記：讀到的最新內容寫進副本。

整批下載進行中如果改了東西，以剛改的為準，不會被下載到的舊資料蓋掉；已刪掉的項目也不會被加回來。

**離線時的圖片**：圖片只存在雲端 Storage，離線時無法取得網址。這次開啟 App 後已經載入過的圖片，瀏覽器可能還留在快取裡，會照常顯示；其他圖片的位置顯示「離線時無法載入圖片」。

**恢復連線時**

- 資料夾樹改從雲端重新載入。
- 斷線前沒存到的內容會自動補存。
- 正在看的筆記如果沒有未存的修改，就從雲端重新讀一次。這篇筆記在離線時讀的是副本，可能比雲端舊；不重新讀的話，接著編輯會蓋掉別台裝置的修改。

**帳號與登出**

- 副本會記下屬於哪個帳號。換成別的帳號登入時，先清掉前一個帳號的副本。
- 按「登出」，或在別的分頁登出、登入被伺服器判定失效時，都會清空副本（spec 第 7 節）。

### 離線期間登入權杖過期

Supabase 的登入權杖約 1 小時過期，平常由 supabase-js 自動換新的。離線時換不到新的，supabase-js 會把登入狀態回報成「未登入」（實際上 refresh token 還在，只是暫時連不到伺服器）。如果直接照這個狀態顯示登入表單，**隔天沒網路時打開 App 就看不到任何筆記**。

做法：沒有有效登入、但這台裝置還有副本時，就用副本記錄的帳號開啟，只能閱讀。登出一定會清除副本，所以副本還在就代表沒有登出。

恢復連線時，App 會立刻請 supabase-js 重試換權杖：

- 成功：自動回到可以編輯的狀態，並重新下載副本。
- 換到之前：上方顯示「已恢復連線，正在確認登入狀態」。supabase-js 換權杖失敗後會冷卻 60 秒才重試，所以最久大約 1 分半；重新整理頁面可以馬上重試。
- refresh token 已失效（例如在別處被登出）：Supabase 會發出登出事件，副本清除，回到登入畫面。

## 驗證

用 Chrome 開部署網址（或 `npm run build && npm run preview`）。開發模式（`npm run dev`）沒有 service worker，斷線後重新整理會打不開頁面，所以要用打包版測。

| # | 操作 | 預期結果 |
| --- | --- | --- |
| 1 | 登入，等幾秒 | 側欄出現「離線副本：時間 更新」 |
| 2 | F12 → Application → IndexedDB → `mdrawer` | `nodes` 的筆數等於資料夾加筆記的數量；`meta` 有你的帳號 id、email 與更新時間 |
| 3 | F12 → Network 把 No throttling 改成 **Offline**，再重新整理頁面 | App 可以開啟，上方顯示「離線中，僅能閱讀。顯示的是 … 存到這台裝置的資料」 |
| 4 | 展開 5 層資料夾，打開幾篇筆記 | 內容都在；有圖片的地方顯示「離線時無法載入圖片」 |
| 5 | 試著打字、貼圖，看看各個按鈕 | 打不了字；新資料夾、新筆記、重新命名、移動、刪除、插入圖片、匯出都不能按；「重新整理」可以按（讀副本） |
| 6 | Network 改回 No throttling | 提示消失，可以編輯，圖片出現，側欄的更新時間變新 |
| 7 | 用另一個瀏覽器（或手機）改某篇筆記，這邊先斷線打開那篇，再恢復連線 | 恢復後編輯框換成另一台改過的內容 |
| 8 | 手機：安裝的 App 開過一次後開飛航模式，再打開 App | 能看到筆記（同第 3、4 項） |
| 9 | 按「登出」，再看第 2 項的 IndexedDB | `nodes`、`meta` 都是空的（spec 第 7 節驗證方式）。可能要在 IndexedDB 上按右鍵 Refresh |
| 10 | 登出後斷線、重新整理 | 顯示登入表單與「目前離線，登入與註冊需要網路」，看不到任何筆記 |

**模擬「離線期間權杖過期」**（可選，不想等一小時的話）：

1. 登入後等側欄出現「離線副本」。
2. F12 → Application → Local Storage → 你的網址 → `sb-…-auth-token`。在值裡找到 `"expires_at":` 後面的數字（秒），改成比現在小的數字，例如 `1700000000`。
3. 照第 3 項斷線並重新整理：仍能以唯讀開啟，帳號顯示在右上角。
4. 恢復連線：幾秒到 1 分半內自動變回可以編輯（想馬上確認可以重新整理頁面）。

自動化測試：`npm test` 裡的 `mirror.test.ts` 用 `fake-indexeddb` 模擬 IndexedDB，涵蓋上表的讀寫規則、修改同步寫進副本、下載期間的修改、換帳號與登出清除、權杖過期時只讀副本。

## 已知限制

- **別台裝置的修改**要等這台下次開啟 App 或恢復連線時才會進副本（開啟那篇筆記時也會更新那一篇）。離線時看到的可能是舊的。
- **斷線前一秒內打的字**還沒存到雲端，會留在畫面上，恢復連線後自動補存。如果離線時切換到別篇筆記或關閉分頁，這些字會遺失（關分頁時瀏覽器會提醒）。L2 改成先寫本機後就不會有這個問題。
- **網路不穩**但瀏覽器以為有連線時，讀取會改用副本，但畫面不會進入唯讀模式，寫入會顯示「無法連線到伺服器」。
- 副本沒有加密，登出時清除（spec 第 8 節）。瀏覽器在儲存空間不足時可能自行清除副本，所以重要資料要定期匯出 ZIP。
